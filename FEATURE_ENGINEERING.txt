PRIORITY 1: X36-CENTRIC FEATURES (3 features)
============================================

Feature 1: X36/X35 (Cooling Imbalance Ratio)

  Formula: X36 / (X35 + 1e-6)

  Justification:
    • X36 has highest SHAP values in baseline model (dominant driver)
    • X35 has 259% relative instability (viz_06_instability.png)
    • Their ratio captures cooling imbalance patterns
    • High ratio indicates X36 >> X35 (potential defect condition)

  Data Cleaning:
    • Handle division by zero: Add 1e-6 to denominator
    • Replace non-finite values with 0
    • Preserves valid ratios, prevents NaN propagation

  Defect Indicator:
    • Extreme ratios (very high or very low) correlate with defects
    • Captures cooling instability at system level

  Expected Range:
    • Normal: 0.9-1.1 (relatively balanced cooling)
    • Defect: 0.5-2.0+ (severe imbalance)


Feature 2: X36/X34 (Alternative Cooling Ratio)

  Formula: X36 / (X34 + 1e-6)

  Justification:
    • X34 also in cooling block (25-36), 240% instability
    • Different denominator captures different aspect of imbalance
    • Provides redundant check on X36 dominance
    • Increases robustness of cooling pattern detection

  Relationship to Feature 1:
    • Correlated but different patterns
    • Both high → severe cooling issues
    • Divergence → localized cooling problems

  Value Add:
    • Independent perspective on X36 behavior
    • Catches edge cases missed by X36/X35 alone


Feature 3: X36×X41 (Cooling×Control Interaction)

  Formula: X36 * X41

  Justification:
    • From EDA interaction analysis (eda_interactions_analysis.csv)
    • Risk score: 39.31% (highest danger interaction)
    • When both X36 and X41 high → 39% of coils are defective
    • Captures non-linear relationship

  Domain Meaning:
    • X36: Cooling parameter
    • X41: Control parameter
    • Their product: Combined cooling-control stress
    • High product → extreme operating conditions

  Defect Indicator:
    • X36×X41 > threshold indicates high defect probability
    • Captures synergistic effect (multiplication not addition)

  Example:
    • X36=100, X41=0.01 → product = 1
    • X36=200, X41=0.02 → product = 4 (product sensitive)

  Justification:

Feature 6: X34-X36 (Cooling Parameter Difference)

  Formula: X34 - X36

  Justification:
    • Captures divergence between cooling zones
    • Subtraction (not division) measures absolute difference
    • Identifies zones moving in opposite directions
    • Indicates loss of cooling coordination

  Insight from Conditional Behavior:
    • In normal coils: X34 and X36 move together (correlation)
    • In defects: They diverge (loss of coordination)
    • This feature detects breakage of coordination pattern

  Interpretation:
    • X34 > X36: Zone 34 hotter than zone 36
    • X34 < X36: Zone 36 hotter than zone 34
    • |X34-X36| large → process instability

PRIORITY 4: ROW-LEVEL STATISTICS (3 features)
==============================================

Feature 12: row_mean (Coil Signature Average)

  Formula: mean(X1, X2, ..., X49)

  Justification:
    • Summary statistic across all features
    • Represents overall coil operating level
    • High row_mean → hot coil (more stress)
    • Low row_mean → cool coil (less stress)

  Defect Indicator:
    • Extreme coil temperatures correlate with defects
    • Not a feature, but a system health indicator

  Interpretation:
    • Normal: row_mean 500-1000 (typical operating range)
    • Defect: Often row_mean extremes (very hot/cold)


Feature 13: row_std (Coil Parameter Variability)

  Formula: std(X1, X2, ..., X49)

  Justification:
    • Measures inconsistency within coil parameters
    • High row_std → parameters scattered (unstable coil)
    • Low row_std → parameters synchronized (stable coil)

  Domain Meaning:
    • Different zones should work together
    • High variance across zones → loss of coordination
    • Coordination loss → defect risk increases

  Example:
    • Stable coil: All parameters in 500-600 range (std = small)
    • Unstable coil: Parameters range 100-1000 (std = large)
    • Unstable coil more likely to have defects


Feature 14: instability (Coefficient of Variation)

  Formula: row_std / (abs(row_mean) + 1e-6)

  Justification:
    • Normalizes variability by mean (accounts for scale)
    • High CV → high variability relative to mean
    • Dimension-independent metric
    • Directly inspired by viz_06_instability.png insights

  From EDA:
    • X35: 259% CV (most unstable)
    • X34: 240% CV (very unstable)
    • X36: 230% CV (very unstable)
    • These features highly unstable in defect samples

  Row-Level Application:
    • If many features are unstable → row CV high
    • High row CV → coil system instability
    • System instability → defect risk

  Data Cleaning:
    • Handle division by zero: Add 1e-6 to denominator
    • Replace non-finite with 0

================================================================================
IMPLEMENTATION DETAILS
================================================================================

Data Cleaning Protocols:

  Division by Zero:
    • Always add small constant: divisor + 1e-6
    • Prevents numerical instability
    • Preserves signal for valid ranges

  Non-Finite Values:
    • Check with np.isfinite()
    • Replace NaN/Inf with 0
    • Prevents downstream NaN propagation

  Feature Scaling:
    • Not applied during engineering (handled separately)
    • Features normalized before model training

Code Implementation:

  ```python
  # X36/X35 ratio
  with np.errstate(divide='ignore', invalid='ignore'):
      ratio = np.divide(X[:, x36_idx], X[:, x35_idx] + 1e-6)
      ratio[~np.isfinite(ratio)] = 0

  # X36 × X41 interaction
  interaction = X[:, x36_idx] * X[:, x41_idx]

  # row_mean
  row_mean = X.mean(axis=1, keepdims=True)

  # instability (CV)
  with np.errstate(divide='ignore', invalid='ignore'):
      instability = np.divide(row_std, np.abs(row_mean) + 1e-6)
      instability[~np.isfinite(instability)] = 0
  ```

Consistency Across Train/Test:

  ✓ Same engineering applied to both sets
  ✓ No data leakage (statistics from training only)
  ✓ Features generated after imputation
  ✓ No target variable involved in engineering
